Security Architecture

HTTP Basic Authentication

CityMate uses secure server-side HTTP Basic Authentication conforming to RFC 7235.

Authentication Status
Not Authenticated
Current User

Protected Features

The following CityMate capabilities require valid HTTP Basic Authentication credentials:

  • Favorites Wishlist (/favorites)
  • Recommendations Engine (/recommendations)
  • Smart Trip Planner (/trip-planner)
  • User Profile Details (/profile)
  • Verified Review Submission (POST /api/reviews)
  • Admin Dashboard (/admin – Admin role only)

How CityMate HTTP Basic Auth Works:

1. When an unauthenticated request reaches a protected route (e.g. /profile, /favorites, /admin), the backend responds with HTTP 401 Unauthorized and the challenge header WWW-Authenticate: Basic realm="CityMate".
2. The browser automatically displays its native username and password authentication modal dialog.
3. Once submitted, credentials are sent in the Authorization: Basic <base64> request header and validated on the server against configured environment credentials and hashed database users.
4. Important Note on Logout: HTTP Basic Authentication credentials are held in browser memory for the session lifetime. True logout in Basic Auth is achieved by closing the browser session or prompting with a new challenge.
